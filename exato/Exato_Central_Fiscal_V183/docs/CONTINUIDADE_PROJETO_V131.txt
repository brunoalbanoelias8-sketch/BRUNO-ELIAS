PROMPT-MESTRE — CONTINUIDADE DO PROJETO EXATO CENTRAL FISCAL

Quero que você assuma a continuidade integral de um projeto de software que já vem sendo desenvolvido em várias versões. Não trate esta conversa como um projeto novo. Você deve continuar exatamente a linha de raciocínio, as decisões técnicas, visuais e funcionais já estabelecidas.

============================================================
1. PROJETO
============================================================

Nome:
EXATO CENTRAL FISCAL

Empresa/marca:
EXATO SOLUÇÕES CONTÁBEIS

Objetivo geral:
Criar uma Central Fiscal desktop moderna, profissional e robusta para captura, organização, auditoria, consulta e geração de documentos fiscais, com integração aos serviços fiscais utilizados pelo escritório.

O sistema trabalha principalmente com:
- NF-e
- NFC-e
- CT-e
- XMLs fiscais
- DANFE
- DACTE
- Auditoria SAT × XML
- organização de documentos
- relatórios
- análises
- Dashboard
- Exato IA

O projeto deve ter aparência profissional, moderna e empresarial, mas sem perder a identidade da Exato.

============================================================
2. REGRA MAIS IMPORTANTE DO PROJETO
============================================================

NÃO QUEBRE O QUE JÁ FOI VALIDADO.

Antes de alterar qualquer funcionalidade relevante:
1. entender como funciona atualmente;
2. identificar os núcleos protegidos;
3. preservar o comportamento validado;
4. fazer alterações de forma isolada;
5. testar regressão depois das alterações.

Nunca alterar uma função fiscal protegida simplesmente para implementar uma melhoria visual ou funcional em outra área.

Quando houver dúvida entre:
- corrigir uma função existente;
- criar uma nova camada;
- adicionar uma função independente;

preferir a abordagem que preserve o funcionamento já validado.

============================================================
3. REGRA SOBRE VERSÕES
============================================================

Só criar uma nova versão Vxxx quando EU AUTORIZAR EXPRESSAMENTE.

Não criar uma nova versão automaticamente porque identificou uma melhoria.

Durante análise e planejamento:
- registrar melhorias;
- propor arquitetura;
- preparar mudanças;
- identificar arquivos e funções afetados;

mas só gerar Vxxx quando eu disser que pode trabalhar/gerar a próxima versão.

Sempre manter o histórico das versões.

Nunca “corrigir” uma versão antiga silenciosamente.

Cada nova versão deve nascer da versão-base indicada por mim, preservando os recursos validados.

============================================================
4. BASE ATUAL
============================================================

A versão mais recente trabalhada é:

V114

Base atual:
Exato Central Fiscal V114

A V114 foi criada a partir da V113.

A V113 havia introduzido uma primeira evolução do Exato IA com:
- acompanhamento do mouse;
- interpolação de olhar;
- microanimações;
- frases contextuais;
- comportamentos por tela.

Porém, após teste real, ficou claro que isso ainda parecia em parte uma troca de imagens, e não um personagem realmente vivo.

A V114 evoluiu esse ponto para uma renderização procedural contínua.

O usuário considerou que houve melhora, mas afirmou que ainda é possível melhorar bastante.

Portanto:
A próxima evolução do Exato IA deve partir do conceito da V114, mas avançar muito mais.

============================================================
5. EXATO IA — REQUISITO CENTRAL ATUAL
============================================================

O Exato IA NÃO deve ser tratado como:
- GIF;
- sequência de PNGs;
- simples troca de imagens;
- troca de poses;
- animação repetitiva previsível.

O objetivo é criar um personagem digital com sensação de presença, autonomia e vida própria.

A definição aprovada é:

“O Exato IA deve parecer um personagem digital autônomo dentro da Central, e não uma imagem animada.”

PERCEPÇÃO
→ ESTADO

→ DECISÃO

→ REAÇÃO

Ele deve perceber:
- movimento do mouse;

============================================================
7. MOVIMENTAÇÃO DO EXATO IA
============================================================

A animação deve ser procedural/real e perceptível.

O personagem deve possuir:
- micro movimentos;
- respiração;
- pequenos movimentos corporais;
- variações naturais de postura;
- piscadas;
- movimento dos olhos;
- movimento das pupilas;
- pequenos movimentos de cabeça;
- mudanças suaves de expressão;
- pequenas reações;
- pausas naturais.

Evitar ciclos perfeitamente repetitivos.

O sistema deve usar variações controladas para que o usuário não perceba facilmente um loop.

Exemplo de comportamento:
respira
→ pausa
→ pisca
→ olha para o cursor
→ acompanha discretamente
→ volta ao repouso
→ muda um pouco a postura
→ olha para outro ponto
→ pausa
→ reage a algum acontecimento.

============================================================
8. OLHAR DO EXATO IA
============================================================

O olhar é um dos pontos mais importantes.

Não deve simplesmente trocar:
look_left.png
look_center.png
look_right.png

O movimento deve acontecer suavemente.

Desejado:
- acompanhar o cursor;
- antecipar levemente movimentos;
- acompanhar deslocamento;
- voltar ao centro quando necessário;
- olhar para elementos relevantes;
- desviar o olhar ocasionalmente;
- piscar durante o movimento;
- voltar ao comportamento natural quando o cursor para.

O usuário deve perceber que os olhos realmente estão vivos.

============================================================
9. COMPORTAMENTO AUTÔNOMO
============================================================

Mesmo quando o usuário não estiver interagindo, o Exato IA deve continuar vivo.

Ele pode:
- respirar;
- piscar;
- mudar levemente a postura;
- fazer micro movimentos;
- olhar para algum ponto;
- retornar ao repouso;
- ocasionalmente demonstrar curiosidade/atenção;
- permanecer em silêncio.

IMPORTANTE:
Uma IA viva não precisa estar fazendo algo o tempo todo.

O silêncio também faz parte da personalidade.

============================================================
27. STATUS DA AUDITORIA
============================================================

Classificação correta:

CONFORME
→ somente quando há correspondência correta.

SEM CORRESPONDÊNCIA
→ XML sem SAT ou SAT sem XML, conforme o lado analisado.

DIVERGÊNCIA
→ documento correspondente, porém com diferenças relevantes de dados/valor.

ATENÇÃO
→ situação geral que exige revisão, mesmo que existam alguns itens conformes.

IMPORTANTE:
Os mesmos critérios precisam alimentar:
- tabela;
- KPIs;
- filtros;
- Exato IA;
- PDF.

Não permitir que uma tela diga “Conforme” enquanto o PDF mostra divergências.
